# Push notifications (closed / background app)

## Why you only see alerts after opening the app

Marketplace notifications are saved on the **Contabo API**. The phone inbox
loads when the app opens (or polls every ~8s while open).

**System tray push** (when the app is closed) needs FCM from the Contabo
server. Without Firebase service-account credentials on the VPS, FCM is
skipped and nothing appears until you open قۆپچە.

## Fix (Contabo VPS)

1. Firebase Console → Project **qopchaapp** → Project settings → Service accounts  
   → Generate new private key (JSON).
2. On the VPS, put the JSON into `.env` as one line:

```bash
FIREBASE_PROJECT_ID=qopchaapp
FIREBASE_SERVICE_ACCOUNT_JSON='{"type":"service_account","project_id":"qopchaapp",...}'
```

Or mount the file and set:

```bash
GOOGLE_APPLICATION_CREDENTIALS=/app/secrets/firebase-admin.json
FIREBASE_PROJECT_ID=qopchaapp
```

3. Install + restart API:

```bash
cd /path/to/server
npm install
# restart docker / pm2 / systemd so index.js reloads
```

4. Customer app: log in once, allow notification permission, stay logged in
   (FCM token is saved on `/api/auth/me`).

## Behaviour after fix

| App state | What happens |
|-----------|----------------|
| Open / background (process alive) | FCM + local banner from inbox poll |
| Fully closed / swiped away | FCM system notification from Contabo API |
| Windows desktop | No FCM — inbox only inside the app |

## App side (already in code)

- Customers subscribe to topic `new_products`
- Token uploaded to Contabo as `fcmToken`
- Foreground / background local display via `flutter_local_notifications`
- `POST /api/notifications` triggers `pushForNotification` (topic or token)
